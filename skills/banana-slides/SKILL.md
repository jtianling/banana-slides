# Banana Slides

根据用户资料组织内容, 调用宿主图片工具生成每页完整画面, 最后运行附带的 Python 脚本组装 PPTX. 不启动原项目后端, 不运行 banana-cli, 不自行调用模型 API.  

这是 2026-10-12 新增的独立工具流适配. 源项目为 [Anionex/banana-slides](https://github.com/Anionex/banana-slides), 修改版源码在 [jtianling/banana-slides](https://github.com/jtianling/banana-slides/tree/main/skills/banana-slides). 本目录按随附的 [AGPL-3.0](LICENSE) 提供. 向用户交付时同时提供此源码入口.  

---

开始前检查可用工具和 Python 依赖. 需要图片生成工具, shell 或代码执行工具, 以及文件交付能力. 若缺少图片工具, 说明当前无法完成生图, 不用占位图片冒充成品. 依赖声明在 `scripts/requirements.txt`, 只在当前任务执行环境缺少依赖时安装, 不修改用户电脑或宿主服务配置.  

确认主题, 受众, 语言, 总页数和风格. 对已有信息直接使用; 用户指定 N 页时封面也计入 N 页. 未指定比例默认 16:9. 明确交付为图片式 PPTX, 页面可移动和替换, 其中的文字和图表不能逐项编辑.  

先整理每页标题, 要表达的核心内容, 精简的上屏文字和讲解备注. 原始事实, 数字和引用依据用户资料或核实过的来源, 不为填版面编造数据. 先用简洁大纲说明采用的结构, 不在用户已明确要求直接制作时额外加确认门.  

统一整套的色板, 字体风格, 留白, 页码位置和视觉语言. 为每页写完整的生图提示词, 包含画幅比例, 本页目的, 精确文字, 排版和风格. 每次生成一整页画面, 不将整套幻灯片生成为一张拼图. 图片是幻灯片本身, 不画屏幕, 桌面, 投影仪或外框. 保证文字足够大, 四周留安全边距.  

调用当前实际提供的图片工具, 以运行时 schema 为准. 宿主提供 `image_generate` 时, 调用形如 `image_generate({"prompt":"本页完整提示词"})`; 比例和画面要求写在 prompt 中, 不臆造 model, size 或 aspect_ratio 参数. 图片模型由宿主配置, skill 不指定 API 地址或密钥. 按工具的并发限制逐页或小批生成.  

保存每次返回的图片与页码对应关系. 若返回 `files[].localPath`, 使用该真实路径; 不从展示 URL 猜测磁盘路径. 按工具的完成状态处理异步任务, 失败时报告具体失败页. 缺少本地图片时使用宿主提供的文件获取能力, 不读取凭据或拼接私有 API 请求.  

检查生成结果是否覆盖要求的文字, 是否截断, 是否清晰, 页间风格是否一致. 优先使用可用的图片查看工具检查实际图片. 修订只针对有问题的页面; 遵循图片工具的重试和修改授权要求, 不自动无限重生. 无法检查图片时明确告知验证限制.  

---

在任务工作区新建 deck 目录, 将成功生成的图片复制到该目录的 `slides/` 下, 按页命名为 `slide-01.png` 等, 扩展名保留真实格式. 不移动或覆盖用户原文件. 清单中的 image 必须是相对清单目录的本地路径, 不得指向目录之外; PNG, JPEG 和单帧 WebP 均支持.  

在该目录写 `deck.json`, slides 数组的顺序就是 PPT 页序. 完整 schema 在 `scripts/deck.schema.json`. 例如:  

```json
{
  "title": "演示标题",
  "aspect_ratio": "16:9",
  "slides": [
    {
      "title": "第一页标题",
      "image": "slides/slide-01.png",
      "notes": "本页讲解备注和资料来源."
    },
    {
      "title": "第二页标题",
      "image": "slides/slide-02.png",
      "notes": "本页讲解备注和资料来源."
    }
  ]
}
```

定位当前 skill 目录后运行附带脚本, `<skill-dir>` 替换为真实路径:  

```bash
python3 <skill-dir>/scripts/assemble_pptx.py deck/deck.json --output output/presentation.pptx
```

脚本按清单组装, 保留图片比例并居中, 不裁掉内容, 不把图片文字转为可编辑对象. 图片比例与画布不同会留下空边; 若用户要求满版, 应在生图阶段获得匹配比例的图片. 讲解备注写入 PPTX 的备注页. 缺图, 损坏文件和非法清单均以非零退出码失败, 不跳页交付. 已存在的输出不会覆盖; 修改后使用新文件名.  

组装成功后核对输出文件存在, 脚本返回的页数等于用户要求, 并重新读取 PPTX 检查页数和图片. 环境有 LibreOffice 时可渲染核对; 缺少渲染器时不要声称已在 PowerPoint 中检查. 只把最终 PPTX 作为主要成品交付, 不把内部清单当作演示文稿. 如果有 `deliver_file`, 按实际 schema 使用工作区内相对路径交付; 否则使用宿主的附件机制, 不虚构下载链接. 最终回复包含成品链接, 图片式 PPT 的编辑限制及修改版源码入口.
