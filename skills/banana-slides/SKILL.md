# Banana Slides

根据用户资料组织内容, 用图片工具生成无字背景或插画, 再将独立文字与其他元素组装成可编辑 PPTX. 默认交付可编辑版本, 不把完整页面截图当作成品. 不启动原项目后端, 不运行 banana-cli, 不自行调用模型 API.  

这是 2026-10-13 更新的独立工具流适配. 源项目为 [Anionex/banana-slides](https://github.com/Anionex/banana-slides), 修改版源码在 [jtianling/banana-slides](https://github.com/jtianling/banana-slides/tree/main/skills/banana-slides). 本目录按随附的 [AGPL-3.0](LICENSE) 提供.  

---

先确认主题, 受众, 语言, 总页数和风格. 使用已有信息, 不重复确认; 指定 N 页时封面也计入 N 页, 比例默认 16:9. 需要 shell 或代码执行工具及文件交付能力; 需要视觉素材时使用宿主图片工具. 依赖在 `scripts/requirements.txt`, 仅在当前任务环境缺少依赖时安装.  

先整理每页的精确上屏文字, 数据, 讲解备注和布局. 全部标题, 正文, 引用, 页码和图表标签必须可编辑. 使用核实过的来源, 不编造引用或为配图虚构数据. 保存用户要求的内容, 不为了通过对象检查只放一个可编辑标题.  

原版通过图片识别和背景修复, 从整页图片重建独立元素. 本适配直接构建相同的分层结果, 避免依赖额外的 OCR 和图片编辑服务: 生图只负责无字背景及插画, 精确文字由原生文本框负责. 不先把文字画进背景, 再用同样文字覆盖; 用户移动文字后不应露出重复的旧字. 已有整页图片若含字, 不能只套一个文本框就宣称可编辑; 必须先取得去字背景, 或按其风格重新制作无字素材并重排文字, 明确重排会改变原来的排版细节.  

照片与复杂插画保持独立图片, 可移动, 缩放和替换, 其中像素不能逐项编辑. 表格使用原生表格, 数据图使用原生图表; 简单流程图由独立形状和文本框构成. 不把表格或图表截图充作可编辑对象. 当前脚本支持柱状图, 折线图和饼图, 以及矩形, 椭圆和右箭头; 不支持的类型应说明限制, 不静默栅格化.  

---

统一色板, 留白和字体, 先确定文字区域再生成素材. 图片提示词明确要求 no text, no letters, no labels, no watermarks, 并描述需留白的位置. 不要求图片工具渲染整页标题和正文. 遵循工具的实际 schema, 只传它支持的字段; 不臆造模型名, 图片引用或路径. 若只有 prompt 参数, 将比例和构图要求写入 prompt.  

每次生成后使用实际返回的本地路径, 将素材复制到任务工作区 `deck/assets/`. 不从展示 URL 猜测路径. 有图片查看能力时检查素材是否夹带文字, 以及留白和对比度; 无查看能力时明确验证限制, 不声称已视觉检查. 不无限重试, 失败时指出具体素材和失败原因. 纯文字或数据页可以直接使用纯色背景, 不需要为每页强行生图.  

阅读 [分层清单说明](references/editable-deck.md), 写出 `deck/deck.json`. 清单中的文字必须与最终需要显示的内容一致, 不能隐藏在备注里. 元素按从后到前排列, 图片和文字使用不同对象. 坐标使用页面宽高的比例, 字号单位为 pt, 可通过 box 大小控制版面. 素材只使用清单目录内的相对本地路径.  

定位当前 skill 目录后运行:  

```bash
python3 <skill-dir>/scripts/assemble_editable_pptx.py deck/deck.json --output output/presentation.pptx
```

不要调用旧版 `assemble_pptx.py` 的整页图片导出入口. 新脚本拒绝没有可编辑内容的页面, 越界元素, 非法图表数据和无效素材, 不跳页交付. 已存在的输出不会覆盖; 修订时使用新文件名. 图片按比例缩放并居中到指定 box, 不裁切或拉伸.  

---

交付前重新读取 PPTX, 对照清单逐页检查页数, 全部文字, 对象类型, 表格单元格, 图表数据与备注. 文字必须能从文本框读取, 表格必须有 table 对象, 图表必须有 chart 对象和可编辑数据. 修改一段文字后另存临时副本, 重读确认修改保留, 再删除测试副本. 不以“文件能打开”或“有图片”代替可编辑性验收.  

能渲染时渲染后检查遮挡, 文字溢出, 图片夹带文字, 对比度和字体替换. 没有渲染器时说明只完成结构检查, 不声称在 PowerPoint 中验证过. 不通过缩到看不清的字号来掩盖溢出.  

交付最终 PPTX, 不把内部清单或临时副本作为成品. 有 `deliver_file` 时按实际 schema 使用工作区内的真实相对路径; 优先使用工具返回的 deliveryPath, 不虚构链接. 最终回复包含成品, 简短说明文字与数据对象可编辑而照片和插画仍是图片.
